# DSH 对话提醒 0.1.1
> Windows 版 DSH Desktop 在后台时，主对话结束后高亮任务栏按钮并发送静音系统通知。

`dsh-task-notifications` 是第三方 DSH 插件，通过 [GitHub Releases](https://github.com/Magicqy/dsh-task-notifications/releases) 提供预构建安装包。**只支持 Windows 上的 DSH Desktop `0.2.2-rc.5`**；其他 DSH 版本和 macOS 暂未支持。

## 安装与升级

1. 将 `.tgz` 保存到不会随意清理的本地目录，不要解压。也可以直接从本仓库工作副本安装；选择这个方式时，不要在卸载前移动工作副本。
2. 如果已装原型版，先在 DSH 侧栏「插件」卸载旧包 `@local/dsh-taskbar-test`，无论它显示 `0.1.0` 还是 `1.0.0`。旧包和新版共用斜杠命令，不要同时启用；不需要删源文件或手改 DSH 配置。
3. 如果已装本插件 `0.1.0`，也先通过插件页卸载。然后打开「插件 → 添加插件」，输入 `dsh-task-notifications-0.1.1.tgz` 的完整路径，或本仓库工作副本的完整目录路径。安装后点「立即启用」，确认包名为 `dsh-task-notifications`、版本为 `0.1.1`。只有界面提示需要重启时才重启。

禁用或卸载可在同一插件页完成。若要回退并且仍保留旧源码目录，可在卸载正式包后用「添加插件」重新安装旧目录。

## 何时提醒

- DSH 处于后台时，用户主对话真正结束才提醒（正常完成或出错后不再继续）。子代理或工具结束、Goal 自动续跑的中间轮次、仅由定时任务触发的轮次、主动取消都不提醒。
- 后台有任务栏窗口时高亮按钮，切回 DSH 后结束提醒。Windows 决定它是闪烁还是持续高亮。不抢焦点，不改托盘图标。
- 同时向 Windows 提交静音通知。DSH 隐藏到托盘时没有可高亮的窗口按钮，但仍尝试发通知。DSH 在前台时不提醒。
- 默认隐藏对话标题。运行 `/taskbar-title-on` 显示 DSH 当前的对话标题，运行 `/taskbar-title-off` 隐藏未来通知的标题。开关保存在当前 DSH profile。多个对话合并成一次提醒、标题不可用或关闭开关时，仍用固定文案。
- 插件不读取消息正文。DSH 的对话标题可能由消息生成，Windows 也可能在通知中心或锁屏显示并保留标题；关闭开关不会删除历史通知。插件不调用模型或访问网络，不修改注册表或应用安装包。
- 点击通知通过 DSH 已注册的 `dsh://open` 恢复或唤起窗口，不跳转到指定对话；注册无法验证时仍发送通知，但不会附加唤起动作。未加入等待回复、等待审批或 macOS 支持。

## 验收与排查

1. **手动通道测试**：选一个标题不含敏感信息的对话，先保持默认隐藏，再从斜杠菜单运行 `/taskbar-test`，10 秒内切到别的应用。确认通知没有对话标题，直接点击通知，确认 DSH 到前台。然后运行 `/taskbar-title-on`，同样切走再测一次，确认通知显示该对话标题。用 `/taskbar-test-status` 查看最近一次提交结果。这些命令都不调用模型。
2. **自动触发测试**：发送一条需要一点时间处理的普通消息，在回复结束前切到其他应用。结束后应收到「DSH 对话已结束」。再试一次，留在 DSH 前台，预期不提醒。
3. **高亮了但没弹横幅**：从 Windows 任务栏打开通知中心（Windows 11 可按 Win + N），查看系统通知设置是否允许 DeepSeek Harness 通知，并检查勿扰模式。「已提交」表示已交给 Windows，不表示横幅一定弹出。若状态提示助手不可用，也检查 Windows 是否通过组策略限制了 PowerShell。

## 回归测试

在仓库根目录或解包后的 `package` 目录下，用 Windows 上的 Node.js 运行 `npm test`。测试不闪任务栏、不发通知；覆盖暂停 Goal 后的普通对话、模型早期失败、排队或定时轮次、自动续跑、主动取消、并发完成与卸载。另有助手输出校验、超时和取消的模拟测试。

可选：运行 `node check.mjs <DSH主进程PID> "<DSH可执行文件完整路径>"`，附加只读探测窗口归属和通知载荷。正常安装不需要运行测试；包不包含安装脚本和第三方依赖。

## 打包

在仓库根目录运行 `npm pack --offline --ignore-scripts` 生成 `.tgz`。安装包不是 Git 跟踪文件。
